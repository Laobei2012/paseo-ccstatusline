## Behavior and evidence

- All 18 widget types have text expectations using the spec example values and
  ccstatusline 2.2.33 source. Token widgets format only supplied latest-report
  counts; they do not aggregate session history.
- Context percent is clamped to 0–100; missing or invalid denominators hide it.
  The bar uses 16 cells. Token, speed, memory, percentage, and reset duration
  formatting follows upstream defaults. `rawValue` remains unsupported as allowed
  by the spec.
- Missing values hide their widgets; unknown types are reported once. Visible
  segments alone consume theme slots, which reset per line unless continuation
  is enabled. Powerline off, custom/unknown themes, or an absent theme use widget
  colors. The absent-theme path is tested with Powerline both on and off.
- Usage selects exactly one available matching `providerId` entry, takes only
  `five_hour` and `weekly` window IDs, and carries `displayName` for the accepted
  account row. Display labels are not used to infer window identities. The
  fixtures use the observed Task 1 report shape with synthetic account names.
- Speed uses `TokenSample = { atMs, input, output }` (milliseconds and latest
  counters), and returns the current sample as the next baseline. Missing history,
  idle state, resets, unchanged counters, or invalid elapsed time hide estimates.
  If only one direction is measurable, that direction can show while total stays
  hidden. Speed segments have `estimate: true`.
- `hoverText` prepends `Usage: <account>` when known. The existing UI remains the
  Task 1 fixed probe; store and UI wiring are later tasks.
