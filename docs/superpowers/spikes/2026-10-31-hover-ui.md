# Remembered hover view: isolated browser evidence

The real plugin client passed a Playwright check against the isolated patched host app on 2026-10-31. This is browser rendering evidence, not a check of the installed desktop app or native gestures.

The temporary plugin copy used the actual `index.client.tsx`, `client/` and `shared/` from this development integration. A fixture server returned deterministic settings and facts through the real daemon RPC transport. The agent used the mock provider. No real ccstatusline/Claude settings or OAuth tokens were read or changed. The fixture manifest matched the isolated app's version; this branch's development-only manifest and the live plugin were unchanged.

Verified in the browser:

- Text is selected initially. Selecting Colored survives closing and reopening hover and then opening the press surface. Selecting Text in the press surface is remembered by the next hover.
- Long spaced branch text and long unbroken path text remain on one row. All configured rows share one horizontal scroll area. The final Powerline arrow is visible at the right extreme in both themes; title, selector and hidden-widget explanation remain stationary.
- Compact web layout opens the press sheet with the same selected mode. Native touch gestures still need device verification.

The test passed in 7.5 seconds (18.1 seconds including isolated setup/teardown). ## Reproduce with matching worktrees

The [local verification spec](assets/hover/status-hover.spec.ts.txt) lives as a template here because it spans two independent repositories. Copy it into the isolated host app's `e2e/browser/` directory as `status-hover.local.spec.ts`; it uses the host's existing real-daemon Playwright fixtures. Set `CCSTATUSLINE_HOVER_SOURCE` to this integration checkout. Build the host app dependencies and install the packed patched SDK into the plugin as described in the [API draft](../drafts/paseo-hover-content-discussion.md).

From the isolated host worktree, run:

```sh
CI=1 E2E_WORKERS=1 \
  CCSTATUSLINE_HOVER_SOURCE=/tmp/paseo-ccstatusline-hover-integration \
  PLAYWRIGHT_BROWSERS_PATH=/tmp/paseo-hover-browsers \
  EXPO_HOME=/tmp/paseo-hover-expo EXPO_NO_TELEMETRY=1 \
  npm_config_cache=/tmp/paseo-hover-npm-cache \
  npm run test:e2e --workspace=@getpaseo/app -- \
  e2e/browser/status-hover.local.spec.ts --retries=0
```

The temporary cache/browser paths are local setup choices. `CI=1` disables Metro watchers; the macOS watcher limit blocked the first local attempt. The sandbox also blocked terminal-worker process identity inspection, so the isolated browser run required sandbox escalation. The harness starts and stops only temporary daemons on allocated ports. It does not restart or upgrade the installed app or daemon.

The committed host regression test separately covers pointer travel, preview state through label updates, keyboard entry, Enter/Space press activation, Escape focus behavior, client-side navigation dismissal, hide/show, error containment, compact fallback and plugin disable with an open preview. App/SDK typechecks, targeted lint and eight host button-model tests pass. Public release compatibility, host disconnect during an open preview, and native device gestures need further verification before live adoption.
