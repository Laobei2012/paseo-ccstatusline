Shows a ccstatusline-style status pill beside each Paseo agent's composer. The pill displays context, 5-hour usage and weekly usage percentages, with `--` for missing values. Hover for a plain-text summary, or click to open your configured rows in Text or Colored view. The selected view is shared across agents until the plugin or app reloads. Long rows scroll horizontally together, including with the mouse wheel on web/desktop.

Requires Paseo 0.14.0 and a ccstatusline settings file on the daemon machine at `~/.config/ccstatusline/settings.json`, or the path set by `CCSTATUSLINE_SETTINGS_PATH` in the daemon environment. Saved settings refresh every 30 seconds and while the panel is open. Supports model, context, branch, memory, tokens, estimated speed, usage/reset timers and thinking effort, plus Claude skill and output-style widgets. Colored view uses configured colors and built-in Powerline themes.

Account usage requires the proposed agent-scoped usage API in both the Paseo daemon and app, which has not yet shipped in a published release. Older hosts/apps keep other widgets working and show `--` for account usage. Reports describe quotas for the agent’s launch account, not consumption by this agent alone. Missing, multiple or unavailable reports hide usage values. A single report is labeled `Usage: <account label>`. Usage refreshes every 60 seconds and on launch changes, turns, reconnects and panel opening. A routing plugin must reopen the provider session or continue in another agent when switching accounts. Token counts come from the latest agent usage snapshot, not session totals. Speed is estimated from changes between reports. Unavailable widgets and empty rows are omitted; unsupported types are named below the rows. Failed fact refreshes may retain their last good values for up to five minutes. Failed usage refreshes clear usage values.

The plugin reads Paseo agent metadata, model catalogs and provider usage, the ccstatusline settings file, Git branch and system memory on the daemon, and Claude output-style settings. For Claude it fetches up to 100 recent timeline entries only while the panel is open to identify the last explicit skill call. Codex skill detection is unavailable. It does not read authentication tokens, change Claude settings, send prompts to providers, or make its own external network requests. Status data travels from the daemon to connected Paseo clients for display; Paseo's configured sources handle provider usage retrieval.

On compact screens, the host sheet can repeat the tooltip text above the panel. Compact web rendering is verified; native touch gestures remain unverified. The mouse wheel shortcut applies to web/desktop clients.
